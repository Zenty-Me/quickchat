# Spec Delta

## Purpose

让用户保存多个模型服务商档案并在其间切换，每个档案独立保存凭据，并能在设置页当场验证配置是否可用、取到该服务商的模型清单。

## ADDED Requirements

### Requirement: 服务商档案的持久化与切换

系统 SHALL 把服务商配置保存为档案列表加一个 active 指针，每个档案包含 id、显示名称、协议、接口地址和模型；对话请求 SHALL 使用 active 档案。

#### Scenario: 首次运行

- **WHEN** 配置文件不存在
- **THEN** 系统显示设置页，并预置一个 OpenAI 兼容档案（`https://api.openai.com/v1`、`gpt-4o-mini`）作为 active

#### Scenario: 新建并切换服务商

- **WHEN** 用户新建一个档案、填好名称/协议/地址/模型并保存
- **THEN** 该档案出现在服务商下拉中，选中它后对话请求发往它的接口地址与模型

#### Scenario: 修改已有档案

- **WHEN** 用户选中某个档案，改动接口地址或模型并保存
- **THEN** 改动写入该档案，其他档案不受影响

#### Scenario: 不存在的 active 指针

- **WHEN** 配置文件中的 active 指向已删除或不存在的档案
- **THEN** 系统回落到第一个档案，配置文件中不存在任何档案时回落为默认档案

### Requirement: 按服务商存储凭据

API Key SHALL 存入 Windows 凭据管理器，条目以服务商 id 区分，MUST NOT 写入配置文件或日志。

#### Scenario: 保存 Key

- **WHEN** 用户在某个档案的 Key 输入框填入非空值并保存
- **THEN** 该值写入以该档案 id 为 user 的凭据条目，输入框清空并显示"已设置"

#### Scenario: 切换服务商不覆盖已有 Key

- **WHEN** 用户为档案 A 保存了 Key，随后切到档案 B 并保存了 B 的 Key
- **THEN** 两个档案各自保留自己的 Key，切回 A 时状态显示"已设置"

#### Scenario: 留空不修改

- **WHEN** 用户保存档案时 Key 输入框为空
- **THEN** 该档案原有 Key 保持不变

#### Scenario: 删除服务商

- **WHEN** 用户删除一个档案
- **THEN** 该档案从配置中移除，其凭据条目一并删除，active 按回落规则重新指向

### Requirement: 旧版单服务商配置迁移

系统 SHALL 在读取到不含档案列表的旧版配置时，把它迁移为单档案结构，并把旧的全局凭据迁移为该档案的凭据。

#### Scenario: 迁移旧配置

- **WHEN** 配置文件只有 `base_url`/`model`/`hotkey` 且存在旧的 `api-key` 凭据
- **THEN** 系统生成一个以旧地址和模型为内容的档案并设为 active，把旧凭据复制到该档案 id 下，删除旧凭据，此后按新结构读写

#### Scenario: 迁移时无旧凭据

- **WHEN** 旧配置存在但旧凭据条目不存在
- **THEN** 迁移照常完成，新档案的 Key 状态为未设置

### Requirement: 拉取模型列表

设置页 SHALL 提供"拉取模型"操作，按该档案的协议请求服务商的模型列表端点，把结果作为可选建议呈现，同时保留手动输入。

#### Scenario: 拉取成功

- **WHEN** 用户点击"拉取模型"且服务商返回模型列表
- **THEN** 模型输入框变为可搜索的建议列表，用户可从中选择或继续手填

#### Scenario: 服务商不支持模型列表

- **WHEN** 模型列表请求返回 4xx/5xx 或网络失败
- **THEN** 系统清空建议列表、保留手动输入，并提示该服务商不提供模型列表需手动填写

#### Scenario: 拉取结果不落盘

- **WHEN** 用户拉取过模型列表并重启应用
- **THEN** 建议列表为空，模型字段仍显示配置中保存的值

### Requirement: 测试连接

设置页 SHALL 提供"测试连接"操作：先请求模型列表，失败则回落一次单 token 非流式对话；结果 SHALL 显示成功与否、耗时，以及失败原因归类。

#### Scenario: 模型列表可用

- **WHEN** 模型列表请求成功
- **THEN** 显示"认证通过"、模型数量与耗时

#### Scenario: 仅对话可用

- **WHEN** 模型列表请求失败但单 token 对话返回成功
- **THEN** 显示"认证通过 · 模型可用"与耗时

#### Scenario: Key 无效

- **WHEN** 请求返回 401 或 403
- **THEN** 显示"Key 无效"，并包含服务商响应片段

#### Scenario: 地址错误

- **WHEN** 请求返回 404
- **THEN** 显示"接口地址不对"，并包含服务商响应片段

#### Scenario: 模型不存在

- **WHEN** 对话请求返回 400 且响应提到模型
- **THEN** 显示"模型名不存在"

#### Scenario: 不可达

- **WHEN** 请求连接失败或超时
- **THEN** 显示"网络或地址不可达"

#### Scenario: 测试未保存的编辑

- **WHEN** 用户改了地址或模型但未保存就点"测试连接"
- **THEN** 测试使用表单中当前的地址、模型、协议与 Key（Key 为空则用已保存的）

### Requirement: 设置页在固定窗口内的可用性

设置页 SHALL 在内容超过窗口高度时纵向滚动，切换服务商 SHALL 自动保存非凭据字段并重置 Key 输入。

#### Scenario: 内容超出高度

- **WHEN** 窗口高度不足以容纳全部设置项
- **THEN** 设置区域可纵向滚动，顶部标题栏与底部操作按钮保持可用

#### Scenario: 切换服务商

- **WHEN** 用户在一个档案上改了地址/模型后直接切换到另一个档案
- **THEN** 改动写回原档案，界面加载新档案的值，Key 输入框清空
